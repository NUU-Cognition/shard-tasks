# 0.5.0

- **Each finished task gets exactly one review request in Ops** (the rule of the operator, fleet ops-overnight-1109). In `wkfl-task-do_task`, `wkfl-task-create_and_do_task`, and `wkfl-task-do_task_group`, interactive and headless, the agent asks for the review right after the result and the sync of each finished task, and before any close: `ops task review request <ref> --note "<the summary, the commits, and what to check>" --json`. The agent does not wait for a person to ask for it. It records the `itemId` and the reviewer in the `# Task Log` and in the result. A blocked or unfinished task gets no request: the agent reports it with its blocker. A close comes only after the request.
- **The reviewer.** With no `--to`, the reviewer is the owner of the task. A task of a team with no owner refuses with `review_no_reviewer`: the workflows then run the request again with `--to me`. `me` is the operator, because `ops` runs with the sign-in of the operator. The workflows do not guess another reviewer. After a change of the result, the same command to the same reviewer changes the note of the open request (`again: true`) and makes no second request.
- **The task group.** `do_task_group` asks for the review of each finished task in Stage 3, after its result and its sync and before its close. Stage 4 reports the recorded requests and the blockers, and asks for nothing.
- **The result line.** The headless return of each work workflow names the request: `Review: requested of <reviewer> (<itemId>)`, the error code and the review command, or the blocker.
- **Invocations.** The request is part of the step `result` (`do_task`, `create_and_do_task`) and of the step `work` (`do_task_group`). The steps `review` and `summary` report it. The step `close` closes only a task with a recorded request. The step ids do not change, so an open invocation of before still closes. The `return-check` behaviours say the rule, and `do_task_group` has a new behaviour `review-check`.
- **Subtasks.** `knw-task-model` and the init tell a step of the work (a subtask in Strike) from an Ops subtask: Ops has subtasks of one level (`subtask_too_deep` for a deeper placement), and `ops task subtask list|children` shows them.
- **The data mode of the dev launcher** (Ops Task 415). `knw-task-cli` § Work on Dev: a dev build of `ops` uses PROD data by default. For dev data, set `OPS_DATA_MODE=dev`. The order is `OPS_DATA_MODE`, a test run, `NUU_DATA_MODE`, `~/.nuucognition/dev-data.json`, then prod.
- `knw-task-cli`: `ops task create --deliverable` puts the task in the main section of the deliverable (Ops Task 406). It gives the `--to` forms and the JSON output of `ops task review request`.
- No use of a removed command is left: `ops task stage|retype|commit|field|type`, `--outcome` on `ops task close`, and the stages of `task.dev`. An old address `task.dev/<id>` still resolves, and the text says so.

# 0.4.1

- NUU Ops removed the task outcome (operator page feedback, 2026-11-04): a done task is done, with its result. No `completed`, `dropped`, or `superseded`. `ops task close` takes only `--result`, and `--outcome` is an unknown option. Split, merge, and continue close the open old task. The init, `knw-task-model`, `knw-task-cli`, `sk-task-close_task`, `sk-task-split_task`, `sk-task-merge_tasks`, `sk-task-continue_task`, `sk-task-capture_as_task`, and `wkfl-task-do_task_group` lose the outcome. The map of the Projects statuses `deprecated` and `superseded` goes to `done` with a result (and a lineage link for `superseded`).
- `task-sync` writes `done` for each done task: it writes no `deprecated` and no `superseded`. A note of before with one of them becomes `done` at its next `task-sync`.
- A review request loops the reviewer into the task (Ops Task 402, amendment 1), unless the reviewer is the owner: the reviewer hears every comment on the task. `knw-task-model` § Looped In and `knw-task-cli` § Looped In give `ops task loop add|remove <ref> <person>` and the code `loop_full`. `wkfl-task-do_task` and `wkfl-task-review_task` say it. `ops review list` also lists the open requests that you asked of other people (`you asked for`).
